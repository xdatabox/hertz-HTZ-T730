Add an optional --atomic flag to the `insert` and `upsert` CLI commands in sqlite-utils. Today an import that fails partway through (bad row, type error, constraint violation) leaves the rows that were already committed in the table, and any table or column the import created stays behind. With --atomic the whole import should run in one transaction: if anything fails, no rows are written and no schema change survives. Default behaviour without the flag must stay exactly as it is, including --batch-size commits and streaming input from stdin. The Python API already has db.atomic(); this is about exposing that guarantee on the CLI.
